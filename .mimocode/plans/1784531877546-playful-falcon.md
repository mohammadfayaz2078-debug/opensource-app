# Plan: Unit Conversion in Stock Management

## Goal
When stock is received (purchase, sale return) or dispatched (sale, purchase return), the system should automatically convert quantities between units in the same category, and create separate stock records for different categories.

## Current State
- `UnitCategory` has `measure_type` enum but NO `reference_unit_id` field
- `Unit` has `uom_type` (reference/bigger/smaller), `factor`, `factor_inv` — conversion factors exist but are never used in stock movements
- `StockService::record()` stores `unit_id` as metadata but does NOT convert quantities
- `StockBalance` unique key is `(product_id, warehouse_tower_id, branch_id)` — unit_id is NOT part of the key, so "last unit wins" behavior exists
- `UnitController::convert()` has working conversion logic but is never called during stock recording

### Step 2: Modify StockService::record() for unit conversion

**File:** `app/Services/StockService.php`

Change the `record()` method to:

1. **Before balance lookup**, resolve the incoming unit's reference unit and conversion factor:
   ```
   $incomingUnit = Unit::find($unitId)
   $referenceUnitId = $incomingUnit->category->reference_unit_id ?? null
   ```

2. **Modify balance lookup** to include unit_id in the lookup when available:
   ```
   // Try exact unit match first
   $balance = StockBalance::where([...existing conditions...])
       ->when($unitId, fn($q) => $q->where('unit_id', $unitId))
       ->first();
   
   // Fallback: find any balance for this product+warehouse
   if (!$balance) {
       $balance = StockBalance::where([...existing conditions...])->first();
   }
   ```

3. **Convert quantity** before applying the movement:
   ```
   if ($balance && $balance->unit_id && $unitId && $balance->unit_id !== $unitId) {
       $convertedQty = self::convertQuantity($quantity, $unitId, $balance->unit_id);
       $quantity = $convertedQty;
   }
   ```

4. **Add static `convertQuantity()` method:**
   ```
   - Load fromUnit and toUnit with their categories
   - If different categories → return original quantity (caller handles separate record)
   - If same category → convert via reference unit:
     quantityInRef = quantity * fromUnit.factor_inv
     convertedQty = quantityInRef * toUnit.factor
     rounded = round(convertedQty / toUnit.rounding) * toUnit.rounding
   ```

5. **Handle different category** — if the incoming unit's category differs from the balance's unit category, create a NEW stock balance record instead of merging:
   ```
   if ($balance && $balanceUnitCategory !== $incomingUnitCategory) {
       // Find or create a new balance with the incoming unit
       $balance = StockBalance::findOrCreateFor(...with incoming unit_id...)
   }
   ```

### Step 3: Update StockBalance unique consideration

**File:** `app/Models/StockBalance.php`

The current unique constraint is `(product_id, warehouse_tower_id, branch_id)` without unit_id. This is correct for the new behavior because:
- Same category, different unit → converted and merged into existing balance
- Different category → creates a new balance (the unique constraint won't prevent this since the old balance has a different unit_id but the same product+warehouse)

Wait — this IS a problem. If unit_id is NOT in the unique key, creating a second balance for the same product+warehouse with a different unit will violate the unique constraint.

**Resolution:** Add `unit_id` to the unique constraint on `stock_balances`.

**File:** New migration `add_unit_id_to_stock_balances_unique.php`
- Drop the existing unique constraint on `(product_id, warehouse_tower_id, branch_id)`
- Add new unique constraint on `(product_id, warehouse_tower_id, branch_id, unit_id)`

## Conversion Algorithm (in StockService)

```
function convertQuantity(float $qty, int $fromUnitId, int $toUnitId): float
    $from = Unit::find($fromUnitId)
    $to = Unit::find($toUnitId)
    
    if ($from->category_id !== $to->category_id)
        return $qty  // Different category — no conversion
    
    // Both units convert via reference unit
    $qtyInReference = $qty * $from->factor_inv
    $converted = $qtyInReference * $to->factor
    $rounded = round($converted / $to->rounding) * $to->rounding
    
    return $rounded
```
